# mail-ad-sync

Связка почтового сервера (Postfix + Dovecot + Postfix Admin) с Active Directory. Почтовые ящики следуют за учётками AD, сотрудники входят в Thunderbird по Kerberos, без отдельного пароля, а к исходящей почте добавляется корпоративная подпись, и письма при этом не ломаются.

Масштаб: ~600 ящиков на двух доменах, ~150 пользователей AD.

## Компоненты

| Файл | Что делает |
| --- | --- |
| `bin/ad-mail-sync` | Каждые 5 минут сопоставляет пользователей AD (по `objectGUID`) с ящиками. В режиме `enforce` создаёт ящики новым сотрудникам и блокирует вход отключённым в AD. Письма им продолжают доставляться |
| `bin/mail-lastseen` | Раз в час записывает последний вход в каждый ящик. Читает journald инкрементально, с сохранённой позиции (cursor) |
| `bin/mail-inactivity` | Находит ящики, которыми не пользовались 365 дней. Без `--apply` только строит отчёт |
| `bin/mail-disclaimer` | Замена `altermime` для Amavis: добавляет подпись в text/plain и text/html, не трогая вложения и подписанные письма |
| `dovecot-sql.queries` | Запросы Dovecot: Kerberos-принципал `sam@REALM` сопоставляется с привязанным ящиком |
| `gpo/Set-ThunderbirdKerberos.ps1` | Logon-скрипт GPO: создаёт или донастраивает профиль Thunderbird. Сначала пробует Kerberos, если не вышло, использует пароль ящика |
| `deploy/enforce.sh` | Безопасное включение блокировок: бэкап, самотест на тестовом ящике, автоматический откат при любой ошибке |
| `deploy/smtp-kerberos.sh` | Включает GSSAPI для отправки только на порту 465, с проверкой до и после и скриптом отката |
| `sql/schema.sql` | Дополнительные таблицы в базе Postfix Admin |
| `systemd/` | Таймеры для синхронизации и lastseen |

## Защита от ошибок

Синхронизация с AD может одним запуском отключить почту всей компании, поэтому в ней несколько уровней защиты:

- **Режим `link` по умолчанию** только записывает связи и ничего не создаёт и не блокирует.
- **Тормоз на ответ AD:** если AD вернул 0 пользователей или на 20% меньше, чем в прошлый раз, запуск прерывается.
- **Тормоз на массовые действия:** если запуск заблокировал бы больше `max_blocks` ящиков, он прерывается. Первая массовая блокировка требует явного `--allow-mass-block`.
- **Ящики никогда не удаляются.** Блокировка лежит в отдельной таблице `mailbox_block`, а не в `mailbox.active`, потому что `active=0` останавливает ещё и доставку.
- **Неоднозначные совпадения не трогаются.** Если на ящик претендуют два пользователя AD, он попадает только в отчёт `--report`.
- **У всех скриптов изменений есть dry run и откат:** `enforce.sh` перед включением проверяет, что заблокированный ящик не может войти, но получает почту, а после разблокировки снова входит.

## Неочевидные моменты

- Dovecot `password_query` не смотрит на `mailbox.active`, поэтому отключённые в Postfix Admin ящики продолжали входить. Блокировку пришлось встроить в сами запросы, с исключением для `lda/lmtp/doveadm`.
- Thunderbird при «любом методе» аутентификации для IMAP пробует GSSAPI и откатывается на пароль. Для SMTP такого отката нет: там «любой метод» означает отсутствие аутентификации. Поэтому скрипт на каждом входе проверяет, можно ли получить билет (`klist get`), и только тогда включает Kerberos для отправки.
- `altermime` для quoted-printable записывал подпись одной строкой, а Postfix резал строки на 998 байтах, и письмо ломалось. `mail-disclaimer` перекодирует тело правильно, а письма, которые не удаётся разобрать и собрать обратно байт в байт, пропускает без изменений.

## Установка (кратко)

```bash
mysql postfix < sql/schema.sql
install -m 0755 bin/* /usr/local/sbin/
install -m 0600 ad-mail-sync.conf.example /etc/ad-mail-sync.conf   # заполнить
install -m 0644 systemd/* /etc/systemd/system/
ad-mail-sync --mode link --dry-run --report                       # посмотреть, что будет связано
systemctl enable --now ad-mail-sync.timer mail-lastseen.timer
```

Зависимости: Python 3.10+, `pymysql`, `ldap3`. Для Kerberos нужны keytab для `imap/` и `smtp/` и `dovecot-gssapi`.
